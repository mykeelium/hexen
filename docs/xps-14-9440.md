# Dell XPS 14 9440 installation path

This is an opt-in implementation for the inventoried Intel Arc 8086:7d55 and
NVIDIA RTX 4050 Laptop GPU 10de:28a1. Automated checks and VM regression cannot
establish physical laptop compatibility. Secure Boot remains disabled and
unsupported in this candidate. Existing VM commands keep their generic profile.

The owner's current Mint baseline has three active 1920x1200 displays at about
60 Hz, middle display primary, through a Tessmart DisplayPort MST KVM over one
USB-C connection. The laptop panel is connected but inactive. Mint's XRandR
connector names must not be copied blindly into Hyprland.

## Before changing the internal disk

1. Restore representative work files from the existing independent backup into
   a temporary location and compare them. Confirm whether the backup can recover
   the whole Mint installation or only personal files. Keep its credentials and
   verified Mint recovery media outside this laptop.
2. Confirm employer requirements for disk encryption, device posture, VPN and
   work accounts. Required apps are Firefox, Slack, Zoom and Go; Zoom and Slack
   remain the separately reviewed manual installs in [app sources](app-sources.md).
3. Review/commit these changes, publish the new commit and require all CI jobs to
   pass. Use that exact full revision for both quickstart stages. An uncommitted
   local tree is not a downloadable installation candidate.
4. Run the read-only inventory from a checkout on Mint or UEFI live media:

   ```sh
   python3 install/hardware.py --profile xps-14-9440
   ```

   This checks the model, both PCI IDs and readable disabled Secure Boot. It does
   not install anything or access a disk. A mismatch stops the profile rather
   than guessing drivers. `--installed` is for installed Arch, not Mint.
5. Establish a reversible graphical hardware test using the intended kernel,
   NVIDIA driver and Hyprland stack. A stock text-mode Arch ISO can establish
   basic boot/network/device discovery, but cannot accept three-monitor Wayland,
   NVIDIA suspend, or Zoom screen sharing. No spare SSD is assumed; do not erase
   Mint just to perform this test.

**Disk gate:** the current installer still accepts only blank whole disks of at
least 40 GiB. It refuses the occupied Mint disk and does not implement dual boot
or an in-place migration. Do not wipe or repartition the laptop to bypass this
while the checks above remain open. The final deliberate disk-preparation step
must follow verified recovery and explicit identification of the internal disk;
never copy `/dev/vda` from a VM. See [quickstart](quickstart.md) for the erase
confirmation and [recovery](recovery.md) for the supported installed layout.

## Installer and first boot

From the verified UEFI Arch media and the exact candidate checkout, preview:

```sh
./install/archinstall/hexen-install.sh --hardware xps-14-9440
```

Only after the disk/backup/hardware gates pass and a deliberately prepared blank
disk is available, add `--install` to that command. Disk selection, LUKS/account
credentials and the final erase confirmation remain interactive. The generator
adds the standard `linux` kernel and the matched NVIDIA/Intel package set to the
base installation; it keeps Limine, UKI disabled and the existing LUKS2/Btrfs
contract. Do not change those choices inside Archinstall to bypass a preflight.

After encrypted boot, use the installed regular account and permanent checkout
at the same full revision, following quickstart stage 2. Run:

```sh
./install/first-boot.sh --hardware xps-14-9440
```

Do not pass `--vm` on the laptop. First boot performs a full Arch update with
`linux`, `mesa`, `vulkan-intel`, `intel-media-driver`, `nvidia-open`, `nvidia-utils`
and `nvidia-prime`, then provisions the selected launcher. Provisioning checks
that installed `linux` matches the cached repository version before module
installation. If it requests an update, perform the normal full update rather
than a partial kernel/driver downgrade. NVIDIA's official open kernel-module
support includes PCI 28A1; package support alone is not hardware acceptance.

The selection is saved in `~/.config/hexen/hardware-profile`. Later normal
`hexen config apply` and `hexen update` reuse it; direct playbook runs also read
it before provisioning. Automatic removal of the XPS profile is refused so that
its GPU configuration is not silently left behind or partially removed.

Provisioning creates stable `/dev/dri/hexen-intel` and `hexen-nvidia` udev aliases,
a managed NVIDIA DRM configuration, and one
`~/.config/uwsm/env-hyprland.d/10-hexen-hardware.sh` fragment. It prefers Intel
while including NVIDIA for connectors routed there. A manually supplied
`AQ_DRM_DEVICES` is respected. Other UWSM and monitor files are preserved; unsafe
symlinks and unmanaged files at reserved destinations are refused.

Reboot after initial setup. There is no live GPU rebinding. Do not force the
`xe` driver, disable either GPU in firmware, or set arbitrary NVIDIA environment
variables as part of these instructions.

## After reboot: accept the actual machine

```sh
python3 install/hardware.py --profile xps-14-9440 --runtime
nvidia-smi --query-gpu=name,driver_version --format=csv,noheader
hyprctl monitors -j
hyprctl configerrors
systemctl --failed
systemctl --user --failed
```

The runtime checker verifies NVIDIA DRM modeset/fbdev and that the aliases point
at the expected PCI GPUs. It never loads modules or changes devices. A successful
check does not accept the screens themselves: confirm all three independent
1920x1200 outputs at the required refresh, ordering and middle-primary behavior.
Use actual Hyprland connector names in machine-local `~/.config/hypr/local.lua`
or the documented display settings workflow; don't edit tracked defaults.

- Switch the KVM away and back; reconnect USB-C; test lid-open/closed behavior.
- Test suspend/resume and lock/unlock both docked and undocked. Keep a working
  TTY/recovery path if graphical login fails; see [desktop recovery](desktop.md).
- Test Wi-Fi, Bluetooth with a real adapter, camera, microphone, speakers,
  headphones, brightness and battery behavior.
- Sign into Firefox and Slack; verify notifications. Join a Zoom test meeting,
  check audio/video, and share each monitor/window through the Wayland portal.
- Run `go version` and build/test a representative work project. Confirm any
  required VPN and employer device requirements.
- Exercise the documented reviewed update and recovery process on the accepted
  candidate, including a newer-kernel transition when one is available.
- Have another person follow the public instructions and record assistance.

Do not declare workstation acceptance until these observations and the backup
restore are recorded. The physical display and work-account steps require the
owner's laptop; they cannot be certified from the rehearsal VM.

## Secure Boot follow-up

Leave it disabled for this installation. LUKS protects stored data, while Secure
Boot verifies boot software. Supporting both requires a deliberate signed boot
chain, key enrollment, repeatable update/signing and tested recovery. Merely
signing Limine without its configuration/artifact verification does not establish
that chain. No firmware keys are enrolled by this profile.
